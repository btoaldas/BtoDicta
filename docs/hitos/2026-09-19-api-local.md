# Hito — API local de transcripción

- Fecha: 2026-09-19
- Spec: 005 — API de transcripción para servicios externos (nivel X)
- Versión: 0.65.0
- RF satisfechos: RF-01 a RF-07. **RF-08 aplazado con razón** (ver desviaciones)
- RNF satisfechos: los cuatro

## Qué se consiguió

Otros programas del equipo pueden pedirle a BtoDicta que transcriba un audio o
pula un texto, en vez de instalar sus propios modelos de varios gigabytes o
contratar otro servicio.

```
POST /transcribir  → Fish Audio, 3 296 ms   ·  motor local, 1 812 ms
POST /pulir        → DeepSeek V4.1 Flash
GET  /estado       → sin token, solo dice si hay alguien escuchando
```

Por dentro usa la misma cascada, el mismo troceo y las mismas cuarentenas que un
dictado. Un camino paralelo habría envejecido distinto.

## Las cerraduras, que era el trabajo de verdad

El riesgo nunca fue que fallara: era que dejara una puerta abierta sin que nadie
se enterara. Cinco cerraduras, cada una con prueba negativa, comprobadas también
desde fuera con `curl` contra el proceso real:

- Apagada de fábrica.
- Solo `127.0.0.1` — desde la IP de la red no responde, y `lsof` lo confirma.
- Token de 43 caracteres, archivo `0600`, comparado en **tiempo constante**.
- Rutas resueltas **antes** de comparar, así que un recorrido de directorios no
  se cuela, y con barra final para que una carpeta de nombre parecido tampoco.
- Cuerpo acotado a 1 MB.

Un rechazo anota el motivo, nunca el token recibido ni la ruta pedida.

## Desviaciones respecto al plan

**RF-08 no se hizo.** Reescribir el comando global `transcribir` sobre la API
exige tocar un archivo que vive fuera de este repositorio (`~/.local/bin`). El
contrato ya está y es estable, así que puede reescribirse cuando se decida;
hacerlo desde aquí sería modificar herramientas de la máquina por cuenta propia.

Dos errores propios durante la implementación, ambos en el ADR 002: el puerto
pasado dos veces a `NWListener`, y el análisis de cabeceras que no leía el token.
El segundo es el que enseña algo: la API rechazaba TODO, también lo legítimo, y
visto desde fuera parecía que la seguridad funcionaba de maravilla.

## Riesgos residuales

1. El token es un secreto en un archivo: quien pueda leer `~/.btodicta` puede
   usar los motores y gastar saldo. Mismo nivel que el `.env` que ya vive ahí.
2. No hay identidad por consumidor: existe «alguien con el token», no «quién».
3. Sin límite de peticiones: un bucle puede gastar saldo de nube deprisa.
4. Si el puerto está ocupado, la API no arranca y lo dice; no busca otro libre.

## Evidencia

- `BTODICTA_APITEST=1` — 16 comprobaciones, casi todas negativas
- `curl` desde fuera: `/estado` responde, todo lo demás se rechaza sin token, y
  desde la IP de la red no hay respuesta
- `lsof -iTCP:8787` → `TCP 127.0.0.1:8787 (LISTEN)`
- Transcripción y pulido reales con audio sintético
- Detalle en `verificacion.md`
